# 04 事件、指令与过滤器

## 导入

```python
from astrbot.api.event import AstrMessageEvent, filter
```

> **必须导入 `filter`**（即 `astrbot.api.event.filter` 这个模块），否则会撞上 Python 内置的高阶函数 `filter`。所有装饰器都挂在它下面。

也可以从 `astrbot.api.all` 直接导入函数形式（`command`、`event_message_type` 等），但插件社区主流写法是 `@filter.xxx`。

## 装饰器总表（4.29.4 全量）

来源 `astrbot/api/event/filter/__init__.py` 的 `__all__` 与 `core/star/register/star_handler.py` 的注册函数。

### 消息事件类（EventType.AdapterMessageEvent）

| 装饰器 | 说明 |
|---|---|
| `@filter.command(name, alias=..., ...)` | 注册指令，发送 `/name` 触发 |
| `@filter.command_group(name, ...)` | 注册指令组，可无限嵌套 |
| `@filter.regex(pattern)` | 正则匹配消息文本 |
| `@filter.event_message_type(EventMessageType.X)` | 按消息类型过滤 |
| `@filter.platform_adapter_type(PlatformAdapterType.X)` | 按平台适配器过滤 |
| `@filter.permission_type(PermissionType.X, raise_error=True)` | 权限过滤 |
| `@filter.custom_filter(...)` | 自定义过滤器 |
| `@filter.button_action(action_id=None)` | 便携按钮交互 |
| `@filter.after_message_sent()` | 消息发送后 |
| `@filter.on_decorating_result()` | 发送消息前（可改结果链） |

### 生命周期 / LLM / Agent 类

| 装饰器 | 触发时机 | 回调参数 |
|---|---|---|
| `@filter.on_astrbot_loaded()` | AstrBot 加载完成 | `self` |
| `@filter.on_platform_loaded()` | 平台加载完成 | `self, ...` |
| `@filter.on_plugin_loaded()` / `on_plugin_unloaded()` | 插件加载/卸载 | `self, ...` |
| `@filter.on_plugin_error()` | 插件处理消息异常 | `self, ...` |
| `@filter.on_waiting_llm_request()` | 已确定要调 LLM、排队等锁**之前**（适合发「思考中」） | `self, event` |
| `@filter.on_llm_request()` | 构造完 LLM 请求、发出之前 | `self, event, req: ProviderRequest` |
| `@filter.on_llm_response()` | LLM 响应后 | `self, event, response: LLMResponse` |
| `@filter.on_agent_begin()` | Agent 开始运行 | `self, event, run_context` |
| `@filter.on_agent_done()` | Agent 运行完成 | `self, event, run_context, ...` |
| `@filter.on_using_llm_tool()` | 调用函数工具前 | `self, event, tool, tool_args` |
| `@filter.on_llm_tool_respond()` | 函数工具返回后 | `self, event, tool, tool_args, tool_result` |
| `@filter.llm_tool(name=None)` | 声明一个可被 LLM 调用的函数工具 | 见下 |

> 事件类型枚举原文（`core/star/star_handler.py` 的 `EventType`）共 17 项，含 `OnCallingFuncToolEvent`、`OnAfterMessageSentEvent` 等。

## 指令

### 基础

```python
@filter.command("hello")
async def hello(self, event: AstrMessageEvent):
    """打招呼"""                 # docstring 会解析成指令帮助
    yield event.plain_result("Hello!")
```

- 指令**不能带空格**（空格会被解析成参数）。
- Handler 必须是插件类的异步方法，前两个参数固定 `self, event`。
- 用 `yield` 返回结果，也可 `return` 一个 `MessageEventResult`（或 `None`）。

### 带参指令（靠类型注解自动解析）

```python
@filter.command("echo")
async def echo(self, event: AstrMessageEvent, message: str):
    yield event.plain_result(f"你发了: {message}")

@filter.command("add")
async def add(self, event: AstrMessageEvent, a: int, b: int):
    yield event.plain_result(f"结果是: {a + b}")   # /add 1 2
```

### 别名

```python
@filter.command("help", alias={"帮助", "helpme"})
async def help_(self, event: AstrMessageEvent):
    yield event.plain_result("帮助信息")
```

### 指令组（可嵌套）

```python
@filter.command_group("math")
def math(self):
    pass                       # 组函数体不需要实现

@math.command("add")
async def add(self, event: AstrMessageEvent, a: int, b: int):
    yield event.plain_result(str(a + b))           # /math add 1 2

@math.group("calc")            # 注意是 .group 不是 .command_group
def calc(self):
    pass

@calc.command("sub")
async def sub(self, event: AstrMessageEvent, a: int, b: int):
    yield event.plain_result(str(a - b))           # /math calc sub 5 3
```

用户输入不完整的子指令时，AstrBot 会渲染指令树帮助。

## 过滤器枚举值

`EventMessageType`（`enum.Flag`）：

```
GROUP_MESSAGE | PRIVATE_MESSAGE | OTHER_MESSAGE | ALL
```

`PermissionType`（`enum.Flag`）：

```
ADMIN | MEMBER | GROUP_ADMIN | SHARED_GROUP_ADMIN
```

`PlatformAdapterType`（4.29.4 全量）：

```
AIOCQHTTP, QQOFFICIAL, QQOFFICIAL_WEBHOOK, TELEGRAM, WECOM, WECOM_AI_BOT,
LARK, DINGTALK, DISCORD, SLACK, KOOK, VOCECHAT, WEIXIN_OFFICIAL_ACCOUNT,
WEIXIN_OC, SATORI, MISSKEY, LINE, MATRIX, MATTERMOST, WEBCHAT, ALL
```

```python
@filter.permission_type(filter.PermissionType.ADMIN)
@filter.command("reload")
async def reload(self, event: AstrMessageEvent):
    ...

@filter.platform_adapter_type(
    filter.PlatformAdapterType.AIOCQHTTP | filter.PlatformAdapterType.QQOFFICIAL
)
async def on_qq(self, event: AstrMessageEvent):
    ...
```

`permission_type` 的 `raise_error=True`（默认）表示无权限时抛错并**停止事件传播**。

## priority

所有注册函数都收 `**kwargs`，其中 `priority` 存进 `StarHandlerMetadata.extras_configs`，**默认 0**。

源码 `core/star/star_handler.py` 的 `StarHandlerRegistry.append()`：

```python
self._handlers.append(handler)
self._handlers.sort(key=lambda h: -h.extras_configs["priority"])
```

即**数值越大越先执行**（降序）。消息管线按注册表的这个顺序依次调用 handler。内置插件正是用 `priority=sys.maxsize - 1` 让「只有一个 @ / 唤醒前缀」的兜底监听器**抢在其它 handler 之前**先跑。

```python
@filter.event_message_type(filter.EventMessageType.ALL, priority=10)
async def early_check(self, event: AstrMessageEvent):
    """priority 越大越早执行；配合 event.stop_event() 可截断后续 handler"""
    ...
```

> `Context.register_commands()` 里另有 `priority: int` 参数（文档写「1-10」），但该方法本身已标注 `@deprecated`，新代码请用 `@filter.command` 装饰器。

## `event.stop_event()`

阻止事件继续向后续 handler / LLM 传播。指令处理完通常**不需要**调用，直接 `yield` 结果即可；只在明确要截断事件时用。

```python
@filter.command("block")
async def block(self, event: AstrMessageEvent):
    event.stop_event()
    yield event.plain_result("已拦截该消息")
```

## 注册检查（调试技巧）

导入插件模块后，可以从全局注册表确认装饰器是否生效：

```python
from astrbot.core.star.register.star_handler import star_handlers_registry
hits = [h for h in star_handlers_registry.star_handlers_map.values()
        if "你的模块名" in str(getattr(h, "handler_module_path", ""))]
print(len(hits), [h.event_type for h in hits])
```

> 要在**导入模块之后**再查询，否则返回 0 只是时机问题。
