# 08 发布、安装与排错

## 三种安装方式（4.29.4）

### 方式一：插件市场

WebUI → 插件 → 插件市场 → 搜索安装。**仅已上架市场的插件可用**；刚建的个人仓库不会出现在市场里。

### 方式二：从 GitHub 仓库地址安装

在插件页填仓库地址。地址栏只填标准地址：

```
https://github.com/YourName/astrbot_plugin_xxx
```

安装器内部流程（源码 `core/star/updater.py` 的 `inspect_repository`）：

1. `normalize_repository_url()` 归一化；
2. `parse_repository_url()` 判定 transport：
   - host 是 `github.com` / `www.github.com` → `archive`（HTTP 拉 raw 文件 / zip）；
   - **其它 host（代理域名、Gitee 等）→ `git`（走 `git clone`）**；
3. archive 分支逐个 GET `metadata.yaml` / `metadata.yml`，拼出的 URL 是：

```
https://raw.githubusercontent.com/{owner}/{repo}/HEAD/metadata.yaml
```

（显式带 `/tree/<branch>` 时改用该分支；不带分支时用 `HEAD`）

4. 校验 UTF-8、≤1MB、YAML 合法、四个必填字段；
5. 下载 zip、解压、调用 `find_plugin_metadata_entry()` 定位 metadata（**允许 zip 内有一层顶层目录**）。

若有独立的「GitHub 代理 / 镜像」输入框，代理前缀单独填那里，拼接规则是 `{代理前缀}/{raw文件URL}`。实测可用前缀：`https://ghfast.top`、`https://ghproxy.net`、`https://gh-proxy.com`。

### 方式三：本地 zip 导入

从本地文件/zip 导入，完全绕开 GitHub 访问，**国内网络最稳**。两种打包都合法：

```
# 带顶层目录（安装器自动识别）
astrbot_plugin_xxx/
├── metadata.yaml
└── main.py

# 扁平（metadata.yaml 直接在 zip 根）
metadata.yaml
main.py
```

### 方式四：终端手动克隆

```bash
cd AstrBot/data/plugins
git clone https://github.com/YourName/astrbot_plugin_xxx.git
# 重启 AstrBot 或在 WebUI 点「重载插件」
```

## 发布到插件市场

1. 建 **public** 独立仓库，仓库根目录直接是插件文件（不要再套一层目录）；
2. `metadata.yaml` 的 `name` 与仓库名一致，`version` 每次发布递增；
3. 加 `logo.png`（1:1，推荐 256×256）；`desc` 控制在一两行内；
4. 清理 `.git/`、`__pycache__/`、`data/`、`node_modules/`；
5. 插件 zip **≤ 16 MB**，超限 CI 直接拒绝；
6. 到 [AstrBot 插件发布页](https://docs.astrbot.app/dev/star/plugin-publish.html) 提交（需注册 AstrBot Cloud 账号），会跳转到 `AstrBotDevs/AstrBot` 仓库生成一个 Issue，等维护者审核；
7. 后续更新只需改 `version` 并 push，市场按版本号提示更新。

## 常见报错速查表

| 报错 | 真实原因 | 处理 |
|---|---|---|
| `未在仓库根目录找到 metadata.yaml 或 metadata.yml。` | **多半是误报**：安装器逐个 GET raw 文件，只要都没返回 200（超时、代理返回 404/403、或把代理前缀拼进地址导致改走 `git clone` 且克隆失败），就抛这句，而不是「网络不可达」。超时只有 15 秒 | ① 地址栏只填标准 `github.com` 地址；② 代理前缀填独立输入框；③ 改用 zip 本地导入；④ 弱网重试一次 |
| `请输入有效的 Git 仓库地址。` | URL 解析失败：带了不支持的 scheme、凭据、查询参数，或路径格式不对（`parts[2]` 必须是 `tree` 且长度 ≥4） | 用标准 `https://github.com/owner/repo` |
| `TypeError: 不受支持的配置类型 number。支持的类型有：dict_keys([...])` | `_conf_schema.json` 用了 `number` | 改 `int` / `float`，见 [02 配置 Schema](02-配置Schema.md) |
| `插件元数据校验失败：metadata.yaml 中缺少必需字段` | 缺 `name/desc/version/author` 之一，或字段不是非空字符串 | 补齐四个字段 |
| `metadata.yaml 必须使用 UTF-8 编码` / `格式错误` | 编码不是 UTF-8 或 YAML 不合法 | 转 UTF-8（可带 BOM） |
| `压缩包不是合法的 AstrBot 插件：未找到 metadata.yaml 或 metadata.yml` | zip 里没有 metadata 文件 | 确认打包包含根目录的 metadata |
| `Plugin xxx has neither main.py nor xxx.py; skipping it.` | 目录里没有入口文件 | 加 `main.py` |
| `AttributeError: 'Xxx' object has no attribute 'context'` | 没调 `super().__init__(context)` | 补上 |
| `TypeError: Image.__init__() missing 1 required positional argument: 'file'` | `Image` 的 `file` 必填 | `Image(file="")` 后再赋 `url` |
| `Image processing in reply chain failed ... HTTP 400` | QQ 图片 rkey 失效 / 版本不匹配（预处理阶段 WARNING） | 无害但图进不了 LLM；用 [06 章](06-LLM钩子与图片管线.md) 的 `on_llm_request` 方案补图 |
| `retcode=1400 packetBackend 不可用，不支持当前QQ版本架构` | QQ 版本超出协议端 Packet 映射（群文件链路） | 降 QQ 版本到协议端支持的范围，或换协议端；插件修不了 |
| `Dependency conflict in plugin ...` | `requirements.txt` 与主环境冲突 | 精简依赖、放宽版本约束 |

## 调试流程

1. **看日志**：`[Core][ERRO][v4.x.x] [star.star_manager:1440]: ----- Failed to load plugin xxx -----` 后面紧跟 Traceback，定位到具体行。
2. **重载**：改代码后在 WebUI 插件页点刷新图标；加载失败的插件在「加载失败插件」列表里点「重载」。
3. **先看加载阶段，再看运行阶段**：`_conf_schema.json` 非法、`metadata.yaml` 缺字段、`__init__` 抛异常都属于**加载阶段**，插件根本不会实例化；指令不触发、结果不返回属于**运行阶段**。
4. **本地静态验证**（不启动 AstrBot 也能查掉大半问题）：

```bash
python -m py_compile main.py
python - <<'PY'
import json, pathlib, tempfile, os
from astrbot.core.config.default import DEFAULT_VALUE_MAP
from astrbot.core.config.astrbot_config import AstrBotConfig
from astrbot.core.star.updater import _PluginUpdater as U

s = json.loads(pathlib.Path("_conf_schema.json").read_text(encoding="utf-8-sig"))
assert not {k: v["type"] for k, v in s.items() if v["type"] not in DEFAULT_VALUE_MAP}
AstrBotConfig(config_path=os.path.join(tempfile.mkdtemp(), "c.json"), schema=s)
print("schema OK")

import yaml
m = yaml.safe_load(pathlib.Path("metadata.yaml").read_text(encoding="utf-8"))
U.validate_plugin_metadata(m, "metadata.yaml")
print("metadata OK")
PY
```

5. **注册检查**：导入模块后查 `star_handlers_registry.star_handlers_map`，确认装饰器都挂上了（要在导入之后查，否则是 0）。
6. **zip 校验**：

```python
from astrbot.core.star.updater import _PluginUpdater as U
print(U.inspect_plugin_archive("plugin.zip"))
```

## 版本与环境

- 4.29.4 要求 **Python ≥ 3.12**，沙盒/部署环境用 3.11 会装不上；
- 手机端「AstrBot 泡泡版」内置的就是 AstrBot 组件，插件机制与桌面版一致；
- 三套文件系统互不相通：泡泡版 App 内部、NapCat 容器 `/root/napcat_instances/...`、以及其它 AI 客户端的 Linux 工作区/Rootfs。要改哪边的文件，就得用哪边自己的终端。
